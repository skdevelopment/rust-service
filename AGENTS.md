# AGENTS.md - RustService

Agent-focused development context for RustService, a Tauri + React Windows desktop toolkit.

## Project Overview

- **Stack**: Tauri 2.12 (Rust backend) + Vite + React 18 + TypeScript + TailwindCSS v4 + shadcn/ui
- **Target Platform**: Windows 10/11 only
- **Purpose**: Portable desktop toolkit for computer repair technicians

## Dev Environment

### Prerequisites
- Windows 10/11
- Bun (https://bun.sh/)
- Rust toolchain (https://rustup.rs/)

### Commands
```bash
bun install            # Install frontend dependencies
bun tauri dev          # Run in development mode (some features require admin)
bun tauri build        # Build → src-tauri/target/release/rustservice.exe (+ NSIS installer)
bun run typecheck      # tsc -b (app + vite config)
bun run lint           # ESLint (TypeScript + React hooks rules)
cd src-tauri && cargo test     # Rust unit tests; also regenerates src/bindings.ts
cd src-tauri && cargo clippy --all-targets -- -D warnings
```

CI runs all of the above and fails if `src/bindings.ts` is out of date.

### Version alignment
`tauri build` refuses mismatched Tauri packages. Keep these on the same
**minor** version (npm uses `~` ranges for this reason):

| Rust crate | npm package |
|------------|-------------|
| `tauri` | `@tauri-apps/api` (and `@tauri-apps/cli`) |
| `tauri-plugin-dialog` | `@tauri-apps/plugin-dialog` |
| `tauri-plugin-opener` | `@tauri-apps/plugin-opener` |

## Conventions

### IPC (Tauri commands)

The frontend calls the backend **only** through the generated bindings:

```ts
import { commands } from '@/bindings';

const settings = await commands.getSettings();
await commands.agentReadFile(path, null, null, true); // positional, typed
```

`src/bindings.ts` is generated by tauri-specta from the Rust command
signatures, so a renamed or mistyped argument is a `tsc` error instead of a
runtime failure. Errors are thrown (`ErrorHandlingMode::Throw`), so
`try/catch` works as with `invoke`. Optional Rust arguments are `T | null` and
must be passed explicitly.

### Adding a Tauri command
1. Write the function in the right `src-tauri/src/commands/*` module:
   ```rust
   #[tauri::command(async)]   // keep work off the UI thread; use `async fn` + proc::blocking for long work
   #[specta::specta]
   pub fn my_command(some_arg: String) -> Result<MyType, String> { ... }
   ```
   Types crossing IPC derive `serde::Serialize/Deserialize` **and** `specta::Type`
   and use `#[serde(rename_all = "camelCase")]`.
2. Add it to `collect_commands![...]` in `specta_builder()` in `src-tauri/src/lib.rs`.
3. Regenerate bindings: run the app in dev, or `cargo test --test bindings`.
4. Call it from the frontend as `commands.myCommand(someArg)`.
5. Add capability permissions in `src-tauri/capabilities/default.json` only for plugin APIs.

Never run blocking work in a plain sync `#[tauri::command]` (those run on the
main thread and freeze the window): use `#[tauri::command(async)]`, or an
`async fn` that wraps blocking work in `crate::proc::blocking(...)`.

### Child processes
Use `crate::proc::command(program)` (no console window in the release build)
and `crate::proc::output_with_timeout(&mut cmd, proc::QUERY_TIMEOUT)` for quick
queries. Decode output with `crate::proc::decode_output` (UTF-8, UTF-16LE and the
console code page). Only interactive launches (scripts, shortcuts) use
`std::process::Command` directly so they get a window. Parse output without
relying on English wording.

### Adding shadcn Components
Always use the CLI, never create shadcn components manually:
```bash
bunx shadcn@latest add <component-name>
```
Components use `new-york` style with TailwindCSS v4.

### Creating New Pages
1. Create `src/pages/NewPage.tsx` following existing patterns
2. Export from `src/pages/index.ts`
3. Add to the `TABS` array in `src/App.tsx`
4. Navigate programmatically with `navigateTo(tab, settingsCategory?)` from `@/lib/navigation`

### TypeScript Types
- Types that mirror Rust structs are aliases of `src/bindings.ts`
  (e.g. `export type ServiceReport = B.ServiceReport_Serialize;`) — change the Rust type, not the alias.
- `src/types/` keeps UI-only types, constants and helpers.
- Rust `f32/f64` arrive as `number | null` (NaN/Infinity serialize as null); use `num()` from `@/lib/utils`.

### CSS & Theming
- Use TailwindCSS utility classes wherever possible
- Color scheme variables live in `src/styles/themes/<id>.css`, imported from `src/styles/globals.css`
  (which maps them to Tailwind colors in `@theme inline`)
- Support both light and dark modes via the `.dark` class

## Settings System

### Architecture
- **Storage**: `data/settings.json`, owned by `commands/settings.rs`:
  reads never write; every change is a locked read-modify-write with an atomic
  file replace; a file that fails to parse is backed up
  (`settings.corrupt-<time>.json`) and recovered section by section.
- **Backend types**: `src-tauri/src/types/settings.rs` (and `types/agent.rs` for `agent`)
- **Frontend**: `useSettings()` from `@/components/settings-context`

### Using settings
```tsx
const { settings, updateSetting } = useSettings();
await updateSetting('appearance.theme', 'dark');        // any dotted path, type-checked
await updateSetting('agent.apiKeys.openai', key);

// Text inputs: save after typing stops, not on every keystroke
const [name, setName] = useDebouncedSetting('business.name');
```
`updateSetting` updates the UI immediately and persists only that field.

### Adding a setting
1. Add the field to the Rust struct (with `#[serde(default)]`), deriving `specta::Type`.
2. Regenerate bindings — the TypeScript type and the `SettingKey` paths follow automatically.
3. Add the default to `src/types/settings.ts` (`DEFAULT_*`) if the UI needs one before load.
4. Add the UI control in the relevant settings panel.

### Theme / color scheme
`useTheme()` from `@/components/theme-provider` (backed by `appearance.theme` /
`appearance.colorScheme`). To add a TweakCN scheme: add `.theme-x` / `.theme-x.dark`
CSS in `src/styles/themes/x.css`, `@import` it in `globals.css` (after `default.css`),
then add it to `COLOR_SCHEMES` and the `ColorScheme` union in `src/types/settings.ts`.

## Known Lint Warnings

These CSS warnings are **expected** and can be ignored:
- `Unknown at rule @custom-variant`, `@theme`, `@apply` - TailwindCSS v4 syntax
- `Unknown property: 'app-region'` - Windows-specific CSS for titlebar dragging

## System Info (sysinfo crate)

- Keep a single `System` instance and call `refresh_*()` methods
- CPU usage requires two measurements with `MINIMUM_CPU_UPDATE_INTERVAL` between them
- GPU info via `gfxinfo`, battery via `battery`
- To add data: extend the struct in `src-tauri/src/types/system_info.rs`, collect it in
  `commands/system_info.rs`, regenerate bindings, add a UI card.

## Programs System

- **Config**: `data/programs.json`; **Icons**: `data/programs/icons/`
- Commands: `getPrograms`, `addProgram`, `updateProgram`, `deleteProgram`,
  `launchProgram`, `extractProgramIcon`, `revealProgram`
- Icon extraction uses `ExtractIconExW` (winapi) and the `image` crate.

## Required Programs System

Auto-detection of external programs required by services (BleachBit, AdwCleaner, ...):
- Registry: `REQUIRED_PROGRAMS` in `src-tauri/src/commands/required_programs.rs`
- Detection: recursive search of `data/programs/`, overridable in Settings → Programs
- Services reference program ids in `required_programs` and resolve them with
  `get_program_exe_path("id")`.

## Service System

4-step flow: **Presets → Queue → Runner → Results**.

### Key files
| File | Purpose |
|------|---------|
| `src-tauri/src/services/mod.rs` | `Service` trait, ordered registry, presets |
| `src-tauri/src/services/ctx.rs` | `ServiceCtx`: logs, findings, cancellable child processes, result |
| `src-tauri/src/commands/services/runner.rs` | Run state machine (start, pause, resume, cancel, parallel scheduler) |
| `src-tauri/src/commands/services/reports.rs` | Report storage, editing, statistics, text export, retention |
| `src/components/service-run-context.tsx` | Run state + event listeners for the UI |
| `docs/adding-services.md` | Guide for adding a service |

### Behaviour
- `run_services` returns the report as soon as the run starts; progress arrives via
  `service-state-changed`, `service-progress`, `service-log` and `service-completed`.
- Cancel stops queued services **and kills the running service's child process**;
  the run reports `cancelled` once the worker exits. Cancel also works while paused.
- Pause takes effect between services (in parallel mode: no new services start).
- Every exit path (success, cancel, error, panic) finalizes and saves the report.
- Queue items have unique ids; results carry `queueItemId`, so the same service can be
  queued twice. Use `findResultForItem` / `resultKey` from `@/types/service` in the UI.
- Report settings apply: auto-save, include logs, retention days.

### Parallel execution (experimental)
Services sharing an `exclusive_resources` tag are serialized; others run concurrently.
Tags: `network-bandwidth`, `cpu-stress`, `disk-exclusive`, `disk-heavy`, `filesystem-scan`.
`dependencies` must run earlier in the queue.

## Animation System

Framer Motion, toggled by `appearance.enableAnimations`. Import `useAnimation`,
`motion`, `AnimatedList`, `AnimatedItem` from `@/components/animation-context` and use
the presets (`fadeIn`, `fadeInUp`, `fadeInScale`, `slideInLeft/Right`,
`staggerContainer`, `staggerItem`, `hoverScale`, `hoverLift`). When disabled,
`motion.*` renders plain elements.

## Agent System

See `docs/agent-system.md`. In short:
- `AgentSessionProvider` (mounted above the tabs) owns the conversation and runs every
  turn through one serialized queue.
- `src/lib/agent-tools.ts` is the single tool registry (schema, approval, activity, sidebar, executor).
- Approval modes: `always` (default), `whitelist` (backend-checked simple commands), `yolo`.
- The agent's file tools cannot touch `settings.json` or the agent database.

## MCP Server (Remote Control)

`src-tauri/src/mcp/`. JSON-RPC over HTTP at `POST /mcp` with `Authorization: Bearer <key>`.
Listens on `127.0.0.1` unless "Allow network access" is enabled, refuses browser
requests and non-local `Host` headers, and applies setting changes immediately.
Its tools call the same backend functions as the in-app agent (same path policy).
MCP clients act **without approval**. See `docs/agent-system.md`.
